# Змейка Гамильтона

Головоломка на движке классической Snake II. Змейкой **нельзя управлять** — игрок
заранее прокладывает ей **рельсы**: замкнутый маршрут без самопересечений. Потом
змейка бесконечно бежит по этому кольцу, ест еду и растёт.

Уровень пройден, если змейка выросла настолько, что закрыла собой всё свободное
поле. Это возможно, только если рельсы проходят через **каждую** свободную клетку
ровно один раз — то есть образуют гамильтонов цикл. Отсюда и название.

## Запуск

Открыть `index.html` в браузере. Либо, чтобы не зависеть от ограничений `file://`:

```bash
python -m http.server 8123
```

Сборка релизных файлов:

```bash
python tools/build_single.py
```

Команда создаёт:

* `dist/vk-games.zip` — архив с `index.html` в корне для размещения игры VK;
* `dist/gamilton-snake.html` — версия одним файлом для обычного хостинга;
* `dist/artifact.html` — та же игра без обвязки `<html>/<head>/<body>`.

## VK Mini Apps

В `index.html` подключён VK Bridge с CDN
`https://unpkg.com/@vkontakte/vk-bridge/dist/browser.min.js`.
Интеграция находится в `js/vk-games.js` и доступна игре как `window.VKGames`.
При старте адаптер вызывает `VKWebAppInit`. Локально игра работает с
`localStorage`; настоящие рекламу и облачные сохранения проверяют при
запуске внутри приложения VK или Одноклассников.

Адаптер включает:

* `VKWebAppShowNativeAds` с форматом `interstitial` при переходе между пройденным
  и следующим уровнем; ошибка рекламы не мешает переходу;
* рекламу с форматом `reward` по кнопкам `🎬` для закрытых уровней; награда
  выдаётся только после ответа с `result: true`;
* предзагрузку роликов через `VKWebAppCheckNativeAds` — при старте и после
  каждого показа. Без неё первый `VKWebAppShowNativeAds` часто отвечает, что
  рекламы нет в наличии. Оба вызова идут с `use_waterfall: true`;
* один повтор показа, если клиент отказал быстрее чем за 2.5 с: столько ролик
  идти не мог, значит его просто не было в наличии. Отказ после этого срока —
  это закрытый игроком ролик, и второй раз он не запускается;
* отказ `error_code: 20` (`No ads`) не повторяется вовсе: рекламная сеть
  сообщает, что подходящего ролика нет, и за доли секунды он не появится.
  Игроку это показывается словами «сейчас нет подходящей рекламы»;
* повторные `VKWebAppInit`, если клиент не успел ответить за 2.5 с. Раньше
  единственная неудачная попытка навсегда отключала рекламу и облако; теперь
  адаптер шлёт до трёх повторов и сообщает игре событием `vkplatformchange`,
  по которому кнопки `🎬` включаются задним числом;
* текст ошибки VK в строке состояния, чтобы «реклама не работает» отличалось
  от «ролик закрыли раньше награды» (`VKGames.describeError`). В консоль
  причина тоже уходит текстом: голый объект ошибки печатается как `Object`
  и ничего не объясняет;
* проверку поддержки методов через `bridge.supportsAsync` — `bridge.supports`
  объявлен устаревшим. Ответ кэшируется: `canShowAds()` зовётся на каждой
  перерисовке полосы уровней и обязан оставаться синхронным;
* `VKGames.diagnoseAds()` — сводка для консоли живого клиента: доступность
  SDK, поддержка методов, состояние предзагрузки и свежий ответ
  `VKWebAppCheckNativeAds` по обоим форматам;
* остановку анимации и отключение HTML-аудио/видео на время рекламы или потери фокуса;
* загрузку и запись строкового JSON через `VKWebAppStorageGet` /
  `VKWebAppStorageSet`, с локальным сохранением при недоступности платформы;
* объединение частых правок рельсов в один облачный запрос и немедленную запись
  побед/разблокировок;
* определение Одноклассников по `vk_client=ok`;
* полноэкранный режим и реакцию на `VKWebAppUpdateConfig`, включая размеры и
  безопасные отступы экрана.

Автоматическая проверка адаптера без сетевых запросов:

```bash
node tools/test_vk_integration.js
```

В игре нет внутриигровых покупок или магазина. Настройка платёжного callback
для этой игры не требуется.

## Как устроено

```
index.html          разметка и тексты
css/style.css       оформление (тёмный корпус + «жидкокристаллический» экран)
js/levels.js        карты уровней (генерируются из tools/levels.py)
js/solver.js        построение гамильтонова цикла — подсказки 25%, 50% и 100%
js/vk-games.js      VK Bridge, реклама, жизненный цикл и облачные сохранения
js/game.js          модель поля, рисование рельсов, симуляция и анимация забега
mazes/*.jpg         исходные скриншоты лабиринтов Snake II
tools/              разбор скриншотов, карты, офлайн-решатель, сборка
```

### Поле

Разбор скриншотов (`tools/extract_mazes.py`) даёт поле оригинала **39 x 17 клеток**
с клеткой 7.13 x 8.84 px; стены везде толщиной ровно в одну клетку. Края поля
замкнуты «бубликом»: уехав за правый край, змейка выезжает слева, за нижний —
сверху. Это видно и по самим лабиринтам: у уровня «Ворота» в боковых стенах
оставлены проёмы, которые иначе вели бы в никуда.

В игре поле расширено до **40 x 17**, а карты подправлены на 1–3 клетки. Причина
арифметическая: гамильтонов цикл существует не на всяком поле. У «Рамки» стена
идёт по краю поля, значит змейка живёт внутри прямоугольника 37 x 15 — обе
стороны нечётные, шахматная раскраска даёт 278 клеток одного цвета против 277
другого, и замкнутый маршрут по всем клеткам невозможен в принципе. Лишняя
колонка чинит это, не меняя вида лабиринта. Остальные правки такие же мелкие:
брусок длиннее на клетку, столб выше на клетку — ровно столько, чтобы уравнять
цвета шахматной раскраски.

### Решатель

`js/solver.js` (и его прообраз `tools/solve.py`) строит гамильтонов цикл так:

1. Поле без вертикальных wrap-рёбер — двудольный граф. В нём ищутся два
   непересекающихся совершенных паросочетания (алгоритм Куна).
2. Их объединение — 2-фактор: каждая клетка имеет степень 2, то есть поле
   разбито на непересекающиеся циклы.
3. Циклы сливаются 2-opt-ходами (тут уже разрешены любые рёбра, включая
   вертикальный wrap), пока не останется один — он и есть гамильтонов.

Работает за 2–4 мс на уровень и служит доказательством, что все восемь уровней
проходимы. Проверка офлайн:

```bash
cd tools && python solve.py
```

### Симуляция забега

Змейка идёт по кольцу, значит её положение в любой момент однозначно: голова —
это `(старт + шаг) mod длина цикла`, а длина тела — количество съеденной еды.
Поэтому весь забег считается заранее, за один проход по списку появлений еды
(75–116 тысяч шагов на уровень), а анимация просто «проигрывает» его с
переменной скоростью: начинает примерно с 10 клеток в секунду, долго и плавно
разгоняется, а перед финишем так же плавно замедляется. Быстрая середина показана
как намеренный таймлапс: еда перестаёт мелькать, у головы появляется световой
шлейф, по экрану проходит сканирующий луч и включается отметка ускоренной
прокрутки. Целиком забег укладывается примерно в 24 секунды; есть кнопка
«Промотать». Во время показа сетка и рельсы скрыты, а еда выделена отдельным
оранжево-красным цветом.

После завершения сохраняется рассчитанная запись забега. Панель повтора позволяет
перейти в начало или конец, двигаться на один игровой шаг назад и вперёд,
перетаскивать ползунок в произвольную позицию, ставить воспроизведение на паузу и
снова запускать его с текущей позиции. Повтор не начисляет очки повторно.

Провал выглядит так: еда появляется в клетке, куда рельсы не заходят, змейка
наматывает два круга и останавливается.

### Прокрутка

Страницу прокручивает сам браузер: своего контейнера со скроллом и своей
полосы прокрутки у игры нет. Единственное исключение — `touch-action: none`
на `<canvas>`: жест по полю рисует рельсы, а не прокручивает страницу.

## Управление

Два инструмента, переключаются в панели под полем или клавишей **Tab**.

* **Отрезки** (по умолчанию) — клик ставит начало, следующий клик — конец
  отрезка; дальше каждый клик продолжает рельсы от последней точки. Отрезок
  всегда прямой: направление берётся по большей из двух разниц, линия обрывается
  перед стеной или уже проложенными рельсами. Под курсором пунктиром показано,
  что получится по клику.
* **Кисть** — нажать и вести, рельсы тянутся за курсором; ведёшь назад по себе —
  стираешь. Курсор можно вывести за край поля, рельсы продолжатся с другой стороны.

Обоими: клик по клетке проложенного пути обрезает рельсы до неё, а доведённые до
стартовой клетки рельсы замыкаются в кольцо.

Клавиатура: **стрелки** — тянуть рельсы по клетке, **Backspace** / **Ctrl+Z** —
отменить, **Enter** — замкнуть, **Пробел** — запуск, **C** — очистить.

При черчении на поле показана сетка (каждая пятая линия заметнее), чтобы удобнее
было считать клетки.

Прогресс и нарисованные рельсы сохраняются в `localStorage` под ключом
`gamilton-snake-v1`, а при запуске через VK Bridge — также в VK Storage.
Облачное сохранение разбивается на части, каждая из которых занимает не более
4096 байт в UTF-8. Части пишутся по очереди в два набора ключей
`gameState_a_N` / `gameState_b_N`; после успешной записи всех частей ключ
`gameState` получает описание новой версии с контрольной суммой. Это позволяет
сохранить предыдущую версию при ошибке записи. Адаптер также читает обычный JSON
прогресса, ранее записанный напрямую в `gameState`.
